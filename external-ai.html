外部AI（CLI・Codexアプリ）で翻訳
サブスクの範囲で、AIに任せる ✨

Codex・Claude Code・Gemini CLI などのAI自身に、スプレッドシートを直接読み書きさせて翻訳する方法です。OpenAIなどのAPI課金は不要で、お使いのAIサブスクの範囲内で動きます😊

🙋

こんな人に

こんな方にぴったり
  • すでにCLIやCodex／Claude等のサブスクを使っている
  • 追加のAPI課金を気にせず使いたい
  • 出力をAIと相談しながら仕上げたい・スキルを編集したい
👑 導入の壁と時間はかかりますが、いちばん融通が利く方法です。サブスクの範囲で動くので、追加のAPI課金もありません。
🧠

この方法の仕組み

🔄 AI自身の力でシートを読み書き

翻訳を外部APIに課金して呼ぶのではなく、いま使っているAI（Codex／Claude／Gemini）自身の力で、シートの日本語商品データ（テキスト＋画像）を読み、英語のeBay出品データに変換して書き戻します。

だから別途APIキーの従量課金は不要で、サブスク内で完結します。

🎒

準備するもの

はじめる前に、3つを用意します👇

🛠️ 使えるAIツール

次のいずれかがあればOKです。

  • Codex app
  • Codex CLI
  • Claude Code
  • Gemini CLI

「Codex アプリ」の導入がまだの方へ。インストール手順は別ガイドにまとめています👇

📘 Codexアプリ導入ガイドを見る →
🔌 MCP「google-sheets」の接続 ＝ ここがいちばん大事

シートの読み込みと、翻訳結果の v5インポート への書き戻しを担当するのが Google Sheets MCP です。これが無いと、AIは翻訳できてもシートに書き戻せません（unknown_action や 認証エラー(401) の原因はほぼこれ）。

  • 📊 Google Sheets MCP … シートの読み書き（本体）
  • 🖼️ GAS（doGet）URL … 画像取得専用（書き込み機能なし）
✅ ユーザーがやることは基本3つ（環境により増えることがあります）
  1. 下の指示書全体をコピーして、自分のAI（Claude Code / Codex / Gemini）に貼り付ける
  2. ブラウザが開いたらGoogleアカウントでログイン・承認する
  3. AIが教えてくれるメールアドレスを、翻訳に使うスプレッドシートの「共有」に貼って「編集者」にする

💡 gcloud（Google公式ツール）やNode.jsがパソコンに入っていない場合、AIがインストールを案内することがあります。AIがコマンド実行の許可を求めたら「はい（Allow）」を選んでください。

🔑 使うGoogleアカウントは個人アカウント（gmail.com）を推奨します。会社のGoogle Workspaceアカウントは、組織のセキュリティポリシーによって鍵の作成が禁止されている場合があります。

👑 おすすめ：AIにこのURLを渡すだけ

下のURLをコピーして、自分のAI（Claude Code / Codex / Gemini）に「このページを読んで、書いてある通りにセットアップして」と伝えるだけです。AIがURLの内容を読み取り、鍵作成からMCP接続までを代行します。

https://raw.githubusercontent.com/naokijodan/v5-guidebook/main/ai-setup-guide.md

💡 AIがURLを開けない（ネット制限など）場合は、上のURLをブラウザで開き、表示された内容をすべてコピーしてAIに貼り付けてください。

🔐 鍵ファイル（JSON）はパスワードと同等の機密情報です。GitHubやSNS・チャットに貼らないでください。

各ツールのMCP登録コマンド早見

🅱 Claude Code CLI のコマンド

公式リファレンス: https://code.claude.com/docs/en/mcp

公式ドキュメントに明記されている構文ルール：--env の直後にサーバー名を置くとCLIが拒否します。--transport stdio を間に挟んでください。

claude mcp add --scope user \
  --env GOOGLE_APPLICATION_CREDENTIALS=<鍵パス> \
  --env GOOGLE_PROJECT_ID=<ProjectID> \
  --transport stdio \
  google-sheets \
  -- npx -y mcp-gsheets@latest

登録確認: claude mcp list / 設定は ~/.claude.json に保存されます。

🅲 Gemini CLI のコマンド

公式リファレンス: gemini-cli / mcp-server.md

公式ドキュメントに明記されている構文ルール：gemini mcp add では -- 区切りは不要。--transport stdio はデフォルトなので省略できます。

gemini mcp add --scope user \
  -e GOOGLE_APPLICATION_CREDENTIALS=<鍵パス> \
  -e GOOGLE_PROJECT_ID=<ProjectID> \
  google-sheets npx -y mcp-gsheets@latest

または ~/.gemini/settings.json に直接記述（公式に記載あり）：

{
  "mcpServers": {
    "google-sheets": {
      "command": "npx",
      "args": ["-y", "mcp-gsheets@latest"],
      "env": {
        "GOOGLE_APPLICATION_CREDENTIALS": "<鍵パス>",
        "GOOGLE_PROJECT_ID": "<ProjectID>"
      }
    }
  }
}
🅰 Codex CLI のコマンド（config.toml）

公式リファレンス: https://developers.openai.com/codex/config-reference

~/.codex/config.toml の末尾に追記します（既存の内容は消さないこと）。

[mcp_servers.google-sheets]
command = "npx"
args = ["-y", "mcp-gsheets@latest"]

[mcp_servers.google-sheets.env]
GOOGLE_APPLICATION_CREDENTIALS = "/Users/名前/.config/gcp/sheets-mcp-credentials.json"
GOOGLE_PROJECT_ID = "<ProjectID>"

Windows では鍵パスを "C:\\Users\\名前\\sheets-mcp-key.json" に変更してください。Windowsで npx が起動しない場合の回避策（公式記載ではなく、コミュニティで報告されている方法）として command = "cmd" / args = ["/c", "npx", "-y", "mcp-gsheets@latest"] に書き換える方法があります。まず公式手順を試してください。

🅳 Codex App（GUIアプリ）の登録方法

Unknown（未確認）：Codex Appで設定画面（Settings / Plugins）からMCPを追加できるか、または config.toml の直接編集で反映されるかは、バージョンによって異なる可能性があります。

方法1：上記「Codex CLI」と同じ内容を ~/.codex/config.toml に追記し、アプリを再起動して確認する。

方法2：アプリ内の Settings または Plugins メニューを探し、MCP追加項目があれば以下を入力する：

  • サーバー名：google-sheets
  • コマンド：npx
  • 引数：-y mcp-gsheets@latest
  • 環境変数：GOOGLE_APPLICATION_CREDENTIALS=<鍵パス>、GOOGLE_PROJECT_ID=<ProjectID>
⚠️ どの方法でも、「Google Drive」ではなく「Google Sheets」（セル・行を書き込めるもの）を選んでください。Driveだけだと特定タブへの行の書き込みに対応していないことがあります。
それでも書き込めないときは → 下の「🆘 書き込めないとき」へ

初期設定

最初に一度だけ。順番にすすめれば大丈夫です😊

1
スプレッドシートの共有設定を変える

外部のAIツール（サービスアカウント）に読み取り・書き込みをさせるため、最初に一度だけシートの共有設定を変えます。メニュー ファイル → 共有 → 他のユーザーと共有 を開きます。

共有ダイアログの入力欄に、AIが作った鍵ファイルに書かれているサービスアカウントのメールアドレス（〜@〜.iam.gserviceaccount.com）を貼り付け、権限を 編集者 にして 送信 を押します。

💡 サービスアカウントのメールアドレスの確認方法など詳細は、上の「🔌 MCP「google-sheets」の接続」をご覧ください。

注意

🧱導入に少しハードル

CLIやアプリの導入に少しハードルがあります（最初の環境準備）。慣れるまでは時間がかかるかもしれません。

⏳件数が多いと時間がかかる

1件ずつAIが処理するため、件数が多いと時間がかかります。大量にこなしたいときは、その分の待ち時間を見込んでおきましょう。

🆘

書き込めないとき（unknown_action / 認証エラー）

AIが翻訳はできるのに、シートに書き戻せない――いちばん多いつまずきがこれです。

🔎こんな症状が出ていませんか
  • AIが unknown_action を返す
  • Sheets API で 401（CREDENTIALS_MISSING など）の認証エラーになる
  • 渡したGAS（doGet）URLで書き込もうとして失敗する
  • シートの共有を「編集者」にしても直らない
🔍原因は共有設定ではありません

ebay-translation は、画像取得にGASのURL、シートの読み書きに Google Sheets MCP を使う設計です。GAS URLは画像取得専用で書き込み機能がありません（だから書込を投げると unknown_action になります）。書き込みの本体である Google Sheets MCP が、そのAI環境に接続されていない――これが原因です。MCP接続にはサービスアカウント（鍵ファイル）の作成が必要で、シートを「編集者」にするだけでは不十分です。

🛠️直し方

上の「🔌 MCP「google-sheets」の接続」に戻って、AIにMCPを接続してください。いちばん簡単なのは、そこにある「👑 おすすめ：下の指示書をそのままAIに渡すだけ」の指示書全体をコピーして、お使いのAIに貼り付ける方法です。AIが自動でサービスアカウントの作成から鍵ファイル生成・MCPの登録まで案内してくれます。最後にAIが教えてくれるメールアドレスを、スプレッドシートの「共有」→「編集者」で追加すれば完了です。

🔄それでも無理なとき

連携メニューに Google Drive しか無い等で書込コネクタが用意できない環境では、AIの書き戻しは諦めて、生成された出品データ（CSV）を手でシートに貼る運用に切り替えてください。翻訳データの生成まではできているので、実害は「貼り付けのひと手間」だけです。
